# mcp-trust-check build log

The full narrative history of how `mcp-trust-check` was built, dogfooded and fixed: what each real-world run found and what changed because of it. It moved here from the [profile README](https://github.com/vishalhabib99) on 2026-09-23 so the profile stays short. The text is unchanged.

the three tools above as one [GitHub Marketplace Action](https://github.com/marketplace/actions/mcp-trust-check): installs and runs all three against a target server and posts one combined score/PR comment instead of three separate ones. Static-only mode (mcp-doctor) needs no config beyond a checkout; the full trilogy also needs either a `run` input with the command that launches the server over stdio, or (since `v1.1.0`) a `url` for a server already running over Streamable HTTP, plus optional auth `headers`. A second CI self-test runs the Action by URL against `server-everything` over HTTP on every push (fuzz 100%, reality-check 100%, combined 96%). Also a [metadata-only survey of 10 hosted MCP servers](https://github.com/vishalhabib99/mcp-trust-check/tree/main/docs/hosted-survey-2026-09) (Hugging Face, Microsoft Learn, AWS, Cloudflare and 6 more). I chose not to fuzz other companies' production endpoints, so it reads only what every client reads on connect and makes no tool calls. It found that 2 of 10 servers mark no tool as read-only, and traced one of them to a real registration bug in GitMCP (8.4K★): annotations added six months earlier were silently dropped by the SDK, [reported with the root cause](https://github.com/idosal/git-mcp/issues/266). Self-verified live against the official `@modelcontextprotocol/server-memory` reference server before shipping: doctor 86%/B, fuzz 100%/A, reality-check 100%/A, combined 95.33%/A. 🎥 [35s live demo](https://github.com/vishalhabib99/mcp-trust-check#demo). `v1.1.0`. Most recently, became a Python package too (`pip install mcp-trust-check`, v0.1.0) — `GuardedSession`, the same combined idea applied to a real agent session instead of a CI run: wraps a live `ClientSession` and runs all three tools' now-completed live gates (mcp-doctor's registration checks, mcp-fuzz's latency gate, mcp-reality-check's correctness gate) at their natural point. Deliberately not a naive composition of the three existing call-and-check wrappers, each of which makes its own real call — that would mean two real invocations per logical call, wrong for a non-idempotent or destructive tool. `GuardedSession` calls a tool exactly once and fans the single real response out to each sibling package's own pure per-response functions instead, verified directly with a real call-counting test. Dogfooded live against the official `server-memory` reference server, and confirmed with a completely fresh `pip install` in a clean environment, not just the dev copy.
